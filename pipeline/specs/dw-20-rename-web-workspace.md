# dw-20-rename-web-workspace — spec

## Goal

Finish dw-19's rename (QUEUE.md `dw-20-rename-web-workspace`, user ruling
2026-09-29): the browser workspace folder `web-divination/` becomes
`web-planet-chat/`, its npm package name becomes `web-planet-chat`, and no
live reference to the old name remains. Behaviour is unchanged.

## Non-goals

- No code, behaviour, route, storage-key, env-var or UI change. The app on
  :5173 is the same app from a different folder.
- History is not renamed: commit messages, `pipeline/DECISIONS.md`, logs,
  specs, plans, `docs/features/*.md` (frozen per-feature snapshots), the
  `dw-*` slugs, and the epic file's PATH `pipeline/epics/divination-web.md`.
- No guard rule changes. The architecture and colour guards change only the
  path they walk and the paths in their planted self-checks; every assertion
  stays and no rule is loosened.
- No deploy work (the workspace is LOCAL ONLY by the epic's ruling).
- app-native, packages/core behaviour and the server are untouched except for
  comments/docstrings that name the folder.

## Decided defaults

- **D1 Move.** One `git mv web-divination web-planet-chat` so history
  follows (`git log --follow` works on every moved file). The directory
  rename carries the untracked, ignored contents with it (`node_modules/`,
  `dist/`), and a root `npm install` then re-links the workspace.
- **D2 Package name.** `web-planet-chat/package.json` `name` becomes
  `web-planet-chat`. Nothing imports the package by name; only `--workspace`
  flags name it. Root `package.json` `workspaces` lists `web-planet-chat`,
  and the `test`, `typecheck` and `web` scripts use
  `--workspace web-planet-chat`. `web:server` is unchanged.
- **D3 Lockfile.** `package-lock.json` is regenerated by `npm install` at the
  root, never hand-edited. The only expected lockfile delta is the workspace
  path/name (`web-divination` → `web-planet-chat`, including its nested
  `node_modules/` entries); no dependency version changes. If `npm install`
  changes any version, that is a defect to investigate, not to commit.
- **D4 Rename sweep.** Every live occurrence of `web-divination` (and its
  possessive "web-divination's") is rewritten to `web-planet-chat` in: root
  `package.json`, `.env.example`, `CLAUDE.md`, `docs/ARCHITECTURE.md`,
  `app-native/src/architecture.test.ts`, `app-native/src/color-guard.test.ts`
  (the `WEB_DIR` / `WEB_ROOT` constants, test names and planted paths),
  `app-native/src/rename-guard.test.ts`, `server/tests/test_rename_guard.py`,
  code comments in `app-native/src/chart/Spotlight.tsx`,
  `packages/core/src/**`, `server/app/**` (not migrations — D6),
  `server/tests/test_web_accounts.py`, and the files inside the workspace
  itself. `pipeline/PIPELINE.md`'s "Frontend-facing" definition and the epic
  file's present-tense paths are updated too (both are current docs, though
  under `pipeline/`). Where prose recorded the folder's history ("dw-1 added
  the web-divination workspace"), it reads "added the web workspace (now
  `web-planet-chat/`, renamed by dw-20-rename-web-workspace)".
- **D5 Allowlist.** In `rename-allowlist.json`, the entry
  `"[Ww]eb-divination"` (D3 of dw-19) is REMOVED, so the dw-19 `divination`
  sweep now covers the folder name. Entries whose `path_glob` names a file
  inside the workspace are re-pointed to the new path
  (`web-planet-chat/src/chat/core-planet-chat-legacy-keys.test.ts`,
  `web-planet-chat/src/auth/core-web-account.test.ts`). The rename guards'
  planted self-checks that used `web-divination/...` paths use
  `web-planet-chat/...`; the "recorded exceptions stay green" sample
  `` `web-divination/src` (dw-18-divination-auth) `` becomes
  `` `web-planet-chat/src` (dw-18-divination-auth) ``; and one new planted
  line proves the old folder name is now RED (e.g. `CLAUDE.md`:
  "`web-divination/src` is the third tree"). The guards' header comments stop
  listing "the web-divination folder" among the exceptions.
- **D6 Applied migration.** `server/app/db/web_migrations/001_web_accounts.sql`
  is an applied migration and stays byte-frozen (the same convention dw-19
  applied to 011/012). Its header comment names the old folder, so it gets
  ONE new allowlist entry scoped to that file and the pattern
  `web-divination`, why "applied web migration, byte-frozen". This is the
  single recorded exception; it is history, not a live reference.
- **D7 CLAUDE.md.** Every path and name is updated; rules 1, 2, 5, 8, 13 and
  the Commands section keep their meaning with only the folder name changed.
  The sentence listing what the allowlist holds drops the folder. The
  workspace paragraph notes the rename WITHOUT spelling the old name (which
  would itself be a `divination` occurrence): "renamed from its dw-1 name by
  dw-20-rename-web-workspace".
- **D8 Browser data.** The Vite origin stays `http://localhost:5173`, so
  browser storage (origin-scoped) is untouched; no key migration is needed.
  CORS (`CORS_ALLOW_ORIGINS=http://localhost:5173`) is unchanged.
- **D9 Where the work happens.** The user's live Vite runs from inside
  `web-divination/` in the primary checkout, so implementation and
  validation run in a separate worktree (`../astrology-wt/dw-20-rename-web-workspace`,
  branch `feature/dw-20-rename-web-workspace`) on alternate ports (Vite on
  5174 via `--port 5174 --strictPort`, backend on 8002 against local
  databases only). The move reaches the primary checkout only at landing;
  then the coordinator restarts Vite from the root with `npm run web`.
- **D10 Other worktrees** (`astrology-run`, `astrology2`) are other branches
  and are not touched.

## Architecture

Delta against `pipeline/epics/divination-web.md` (target modules, dependency
rules). No module is created, split or merged; one module's HOME moves.

**Module map (after).**

```
package.json            workspaces: packages/*, app-native, web-planet-chat
web-planet-chat/        was web-divination/ (git mv; contents byte-identical
  package.json            except `name` and folder-naming comments)
  vite.config.ts        repo-relative URLs ('../packages/core/src/', '..') —
                          depth unchanged, so no path logic changes
  src/**                unchanged modules (platform/, chart/, chat/, nav/, …)
rename-allowlist.json   minus the folder entry, plus the D6 migration entry,
                          two path_globs re-pointed
```

**Reuse (verified by targeted reads).** `web-planet-chat/vite.config.ts:24-25`
resolves core and the repo root relative to `import.meta.url`, so the move is
path-neutral. `app-native/src/architecture.test.ts:46` (`WEB_DIR`) and
`app-native/src/color-guard.test.ts:112` (`WEB_ROOT`) are the only places the
guards compute the third tree's location; every other occurrence in those
files is a repo-relative string used in test names or planted fixtures, which
the guards compare against `path.relative(REPO_ROOT, …)` output and so must
change in lockstep with `WEB_DIR`. Both rename guards read the single list
`rename-allowlist.json` with one algorithm (`app-native/src/rename-guard.test.ts`,
`server/tests/test_rename_guard.py`); changing the list changes both.

**Contracts unchanged.** CLAUDE.md rules 1, 2, 5, 8 and 13 name the third
tree by path; each rule keeps its text with the path substituted. The web
workspace still imports core only through barrels, still never imports
app-native (G9 checks specifiers containing the workspace name — it now
checks `web-planet-chat`), and `web-planet-chat/src/theme/tokens.ts` is the
sole colour home. No wire shape, storage key, env var or route changes.

**Forbidden.** No compatibility symlink `web-divination → web-planet-chat`
(it would be a live reference and would let stale scripts keep working
silently). No alias of the old npm package name. No edit to applied
migrations. No relaxation of any guard assertion; the rename guard only gets
stronger (the folder word leaves the allowlist).

**CLAUDE.md amendment.** Path substitution per D4/D7 only; no rule change.

## Acceptance Criteria

Run from the feature worktree root unless a criterion says otherwise.

- **R1 The folder moved with history.** `test -d web-planet-chat && ! test -e web-divination`
  succeeds; `git log --follow --oneline -- web-planet-chat/src/platform/boot.ts`
  lists commits older than dw-20 (e.g. dw-1's `f02e88b` squash or later
  ones); `git diff --stat --find-renames <base>..HEAD` shows the workspace's
  tracked files as renames (R100 or near), not delete+add.
- **R2 Package name and root wiring.** `web-planet-chat/package.json` has
  `"name": "web-planet-chat"`; root `package.json` `workspaces` contains
  `web-planet-chat` and not `web-divination`; `npm run test`, `typecheck` and
  `web` scripts name `--workspace web-planet-chat`.
- **R3 Lockfile regenerated, versions unchanged.** After `npm install` at the
  root, `git status` shows no further lockfile change; `package-lock.json`
  contains no `web-divination`; comparing `packages[*].version` for every
  `node_modules/...` key between the base commit's lockfile and the new one
  (with the workspace path prefix rewritten) shows zero version differences.
  `node_modules/web-planet-chat` is a symlink to `../web-planet-chat`, and
  `node_modules/web-divination` does not exist.
- **R4 No live reference remains.**
  `rg -n --hidden -g '!.git' -g '!**/node_modules/**' -g '!pipeline/' -g '!docs/features/' 'web-divination'`
  prints exactly these four files and no other:
  `server/app/db/web_migrations/001_web_accounts.sql` (D6, applied migration
  header), `rename-allowlist.json` (the D6 entry only),
  `app-native/src/rename-guard.test.ts` and `server/tests/test_rename_guard.py`
  (only inside their D5 planted self-check that proves the old name is red).
  In each of the last three, every matching line is one of those named
  purposes. `rg -n 'web-divination' pipeline/PIPELINE.md pipeline/epics/divination-web.md`
  prints nothing.
- **R5 The rename sweep covers the folder.** `rename-allowlist.json` contains
  no `[Ww]eb-divination` entry; its only entry naming `web-divination` is the
  D6 one. Both rename guards pass
  (`npx jest src/rename-guard.test.ts` in `app-native`;
  `conda run -n astrology pytest tests/test_rename_guard.py -q` in `server`),
  including a self-check that a planted `web-divination/src` line in a live
  file (not the migration) is reported as an offender. Temporarily writing
  `// see web-divination/src` into a scanned live file (e.g. appended to
  `web-planet-chat/src/platform/boot.ts`) turns both guards red; reverting it
  turns them green.
- **R6 Guards walk the new tree, rules unchanged.** In `app-native`,
  `npx jest src/architecture.test.ts src/color-guard.test.ts` passes; the
  guards' `WEB_DIR`/`WEB_ROOT` point at `web-planet-chat`; the number of
  `test(`/`expect(` calls in each of the four guard files
  (architecture, color-guard, both rename guards) is not lower than at the
  base commit (the rename guards may gain the D5 self-check). A planted
  `fetch(` in a new file `web-planet-chat/src/app/planted.ts` turns the
  architecture guard's G3 test red (removed afterwards).
- **R7 Root commands work.** From the root: `npm install` exits 0;
  `npm test` passes (app-native jest then web-planet-chat vitest, both
  green); `npm run typecheck` passes; `npm run build --workspace web-planet-chat`
  succeeds; `conda run -n astrology pytest -q` in `server` has no failures
  beyond those that also fail on the base commit 067ee47 with the same
  environment.
- **R8 The dev server runs from the root.** `npm run web -- --port 5174` (or
  the equivalent Vite invocation from the root through the workspace) serves
  `http://localhost:5174/` with HTTP 200 and an HTML page whose module script
  loads (`/src/main.tsx` returns 200 with JavaScript). After landing, `npm run web`
  from the primary checkout root serves `http://localhost:5173/` with 200.
- **R9 End to end on the real app.** Against a backend on local databases
  only (never the root `.env`'s DATABASE_URL or WEB_DATABASE_URL), the app
  served from `web-planet-chat` loads, the sign-in screen renders in a real
  browser, and a signed-in session (established by minting a web bearer in
  the local web db, as earlier dw acceptance runs did) reaches the six-planet
  home and a `/chat/<planet>` page whose wheel renders and whose planet_chat
  sheets request answers 200. After landing, `http://localhost:5173` loads
  and `GET http://localhost:8000/api/health` reports `db` and `webDb` ok.
- **R10 Docs are current.** `CLAUDE.md`, `docs/ARCHITECTURE.md`,
  `pipeline/PIPELINE.md` and the epic file name `web-planet-chat` wherever
  they describe the current workspace, and CLAUDE.md's commands section
  shows `--workspace web-planet-chat` and `inside web-planet-chat/`.
