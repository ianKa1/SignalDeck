## Non-blocking notes for the plan

- **N1 (D5, R5): fragment anchors and the router.** `a[href="#chart-pane"]` / "↑ Chat" are hash navigations. They push a history entry and fire `popstate`, so `nav/history.ts` `onPop` sets `lastChange()` to `'pop'` and notifies. The path does not change, so the route holds. But after one "Chart ↓" jump, Back lands on the same chat with `#chart-pane` instead of the previous route. That undercuts the spirit of R5. The plan should either use a button with `scrollIntoView` (the selector in D5/R4 then changes to a `data-` attribute) or add an R5 step that clicks the jump link before pressing Back. The first is preferred, and G16 is untouched either way.
- **N2 (D5): wrong "as today" claim.** "the spotlight keeps its frame loop only when visible as today" does not match the code: nothing in `chart/spotlight/` observes visibility (no IntersectionObserver or visibility check). Read the clause as "spotlight behaviour unchanged" and add no visibility gating.
- **N3 (D3 vs W3): click or mousedown.** D3 says "a click outside closes it" and W3 tests "a mousedown outside". Pick one. Mousedown is the safer choice, because a click that starts inside the form, such as a text selection drag, would otherwise close it. CityPicker renders inline with no portal, so its suggestion list counts as inside the popover. Keep it that way.
- **N4 (D2, W6): which i18n keys go.** "the placement-row labels" is vague. `chart.*` holds `placementsTitle`, `bigThree`, `planetTitleHouse`, `ac`, `mc`, `retrograde`, `house` and `timeUnknownNote`, and some of these may be read by `ChartWheel`/`ChartStage`/`format.ts`. Delete only the keys that no remaining file references after the Placements deletion (grep), and keep `format.ts` (`degreeText` is used by ChartStage). W1's `[data-big-three]` selector matches nothing today (the markup uses the `.big-three` class), so assert on the class and text as W1 also does.
- **N5 (D4, W4): the no-data state changes.** With no birth data the stage currently shows ChartStage's empty ring and its invitation (`status.empty`). D4 replaces the stage with the form, so that state and its string may stop being reachable on chat routes. Check whether any ChartStage test asserts the empty ring through the App on `/chat/*` (W8), and keep `status.empty` if ChartStage still renders it elsewhere.
- **N6 (D1): wheel sizing.** `min(pane width, pane height minus the row)` must also leave room for the focus toggle below the disc and the status text. Container-query units or an `aspect-ratio` box inside a `min-height:0` flex child will do it. R1's no-page-scroll check will catch an overflow.
- **N7 (parallel dw-16): merge risk.** dw-16 (implementing) turns birth data into an account-backed cache and adds a one-time import prompt, which may touch `birth-input/` and `useBirthData`. Keep BirthCard's store read behind `useBirthData()` so the merge touches presentation only.
- **N8 (R3): nondeterministic pill.** R3 needs a live reply that carries a pill. Use claude-cli backup mode, and allow a retry or an example-question seed known to produce a placement tag.
