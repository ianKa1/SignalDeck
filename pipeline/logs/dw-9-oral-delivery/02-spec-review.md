A2(d) and A3's "how they bear on each other" are judgment calls, but they have a rubric and can be checked.
3. **Contract and ruling.** The segmenter fits the no-prose-parsing ruling. The ruling guards side FIELDS: structured meaning (mood, refs, dice) must come from structured calls. The `bubble` event carries only an ordinal. It is a lossless re-encoding of the model's own line breaks plus a typographic sentence cap, the text passes verbatim, and nothing about content is extracted or asserted. It is the same kind of transform as line wrapping. Rejecting a special delimiter token keeps call B genuinely open. One caveat: the rationale slightly overclaims, because `shape.chat` does ask the model to put each bubble on its own line, so `\n` is a model-emitted delimiter. It is safe because a misplaced newline only yields another bubble and leaks nothing, unlike a tag. Other contract points: llm.py and main.py are untouched (rule 3, and rule 14's exception is unchanged), bubbles.py is stdlib-only (rule 10), no colour literals (rule 13), and the web arithmetic guard is unaffected. The Architecture section matches the epic (additive `bubble` event, `action` += `deeper`) and defers the epic update to docs-sync. The file:line claims are verified, apart from small drifts (for example `chat-arrive` is at chat.css:96/437, not :98).
4. **Non-goals and defaults.** The non-goals are explicit, and every open point has a decided default. Word count: 1,531 against a ~1,500 budget, which is acceptable.

## Non-blocking refinements

- **N1 (T3 wording).** `_drain` checks `cancel` only when the next chunk arrives, and a generator that is still running cannot be `close()`d from another thread. So while the fake sits blocked, its `finally` cannot run "once the turn ends". Suggested rewording: "after the test sets the fake's event, its `finally` runs within 1 s, and no further chunk is framed." The same applies to the spec's "cancels the provider stream at the cap": in practice it stops at the next provider chunk.
- **N2 (pending lifetime).** Today `useChat` clears `controllerRef` and `pending` as soon as the stream ends. With the pacer, the turn must stay in flight until the pacer's `end`: Send is disabled, Stop stays live, and `canDeepen` is false. Otherwise a new send during a pause would append entries out of order, and W3's "Stop during a pause" would be a no-op once `done` has arrived. The spec should also say that Stop after `done` still stores `stopped` and drops mood and refs.
- **N3 (existing render pin).** `test_divination_render.py::test_topic_is_registered` pins the exact fragment set. It must gain `shape.chat`, `shape.deeper`, `depth.chart` and `depth.none`. It is also a dw-7 merge hunk, because dw-7 adds `self.*` to the same set, so it belongs in "Shared files".
- **N4 (delta non-empty).** The epic's grammar says `delta` is non-empty. B1 and B5 should assert that the segmenter never emits `("delta", "")`, including across chunk boundaries and when held whitespace is flushed.
- **N5 (minimum not structural).** The server enforces only the maximum, so A1's "2–4 slips" depends on the prompt. That is fine as a design choice, but if A1 fails, the fix loop should tune `shape.chat`, not add a server minimum.
