## Non-blocking

- **N1 (important): the refresh deadlocks as specified.** The contract has `refresh` single-flight over `apiFetch('/api/auth/token/refresh')`, mirroring native tokenStore.ts. When the refresh POST itself returns 401, apiFetch (api.ts) calls `provider.refresh()`, which returns the same in-flight promise that is waiting on that apiFetch. Nothing ever resolves. C3's refresh-401 case and DD6's "401 after refresh → signed-out" would hang, and a user with an expired 60-day token would sit at "checking" forever. **Fix:** in `web-divination/src/platform/auth.ts`, send the refresh POST with plain `fetch(apiUrl(...))`, which G3 allows in platform/, or otherwise stop it re-entering the provider. Add a C3 timeout assertion. Native has the same latent bug, which is out of scope and worth journaling.
- **N2: G2 cannot fail.** Vite never exposes a non-`VITE_` shell variable, so a shell `TOKENROUTER_API_KEY` sentinel proves nothing. **Fix:** pin the mechanism with a source check on vite.config.ts: no `envDir`, no `envPrefix` change, `loadEnv`'s third argument is exactly `'GOOGLE_CLIENT_ID'`, and exactly one `define` key is built from `env.GOOGLE_CLIENT_ID` with no spread. Also remember that loadEnv filters by prefix, so `GOOGLE_CLIENT_ID_*` keys would match it.
- **N3: the guard name collides.** `architecture.test.ts` already has G10 (public-API consumers, :28/:935) and G11. Call the new guard G12, and rename it in G1's criterion too.
- **N4: DD8 and DD6 disagree.** With empty KV no request is sent, so without a database the gate shows the button, not "unavailable". Unavailable only appears after a click or from stored tokens. R5 should say "with a pair minted before the restart in KV".
- **N5: R1's "Google button iframe" may not render.** A placeholder client id or an unauthorized origin can stop it. Check for the injected script plus the button slot instead.
- **N6: U1 is missing inputs.** A Venus reply needs an LLM provider in a backend started without `--env-file` (export `ANALYSIS_LLM=claude-cli` or a key). "Exactly one users row" conflicts with the rows R2 minted earlier on the same cluster, so use a fresh cluster or "one row for that email".
- **N7: `verify_oauth2_token` fetches Google's certificates on every call.** Consider a cached transport. The unthrottled route would make an outbound request for every call.
- **N8: GIS locale.** GIS locales are usually `zh_CN`; consider `zh_CN` in W6. vitest `css.include` must add `auth.css` for W6's reduced-motion check.
